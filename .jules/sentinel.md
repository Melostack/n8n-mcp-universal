## 2025-02-27 - [Fix SSRF protection bypass in external trigger handlers]
**Vulnerability:** The application was vulnerable to DNS rebinding in `ChatHandler` and `FormHandler`, because even though `validateWebhookUrl` was verifying the resolved IP, the subsequent `axios` request performed a new DNS lookup for the same hostname. A malicious server could change its DNS record to point to a private IP (e.g. 127.0.0.1) immediately after validation, thereby bypassing SSRF checks during the actual HTTP request. `N8nApiClient.triggerWebhook` was also exposed due to the same lack of DNS pinning logic when instantiating the direct webhook client.
**Learning:** Checking the URL with DNS resolution once and then passing it directly to an HTTP client that performs its own DNS resolution creates a Time-Of-Check to Time-Of-Use (TOCTOU) vulnerability specific to SSRF, known as DNS rebinding. The resolved IP must be passed directly to the HTTP client (DNS pinning).
**Prevention:** Always use DNS pinning. Modify the DNS validation helper to return the resolved IP address, and pass this specific IP directly to the `lookup` parameter of the Axios configuration for subsequent requests.
